# リモートデュエル(β)

実物の遊戯王 OCG のカードを Web カメラ越しに使う、リモートデュエルの補助ツールです。ライフ・フェイズ・チェーン・勝敗を2人で共有でき、相手のカメラ映像を手元で拡大して見られます。身内で遊ぶことを想定しています。

公開版: https://yt-glaceon.github.io/remote-duel/

## できること

| 機能 | 内容 |
|---|---|
| ルーム | 「ルームを作る」で招待リンクを発行する。相手はリンクを開くだけで参加でき、インストールやログインは要らない。どちらかが再読み込みしても、自分の席に戻って続きから再開する |
| LP | 数値か式(`2400*2`、`2500-1900` など)を入れて「ダメージ」「回復」「指定」を押す。Enter はダメージ。先頭に `+` で回復、`=` で指定にもなる。−100・−500・−1000・半分のボタンもある。端数は四捨五入する |
| ターン・フェイズ | ターン数・ターンプレイヤー・フェイズ(公式の名前で表示)。先攻・後攻はボタンで選ぶ。先攻の1ターン目は「次のフェイズ」でメインフェイズ1からエンドフェイズへ進む |
| チェーン | カード名を入れて積み、後から積んだものから「1つ解決」していく |
| コイントス・サイコロ | 結果を2人に同時に表示する |
| 勝敗 | 「勝者」か「引き分け」のボタンで確定する。理由(LP 0・デッキ切れ・特殊勝利・その他)も残せる。LP が 0 になると確定するよう案内が出る。このルームでの通算の戦績を表示する |
| 次のデュエル・やり直し | 決着後の「次のデュエル」は、負けたプレイヤーを先攻にして始める。「やり直し」は勝敗を記録せずに最初から始める |
| 1手戻す・履歴 | 直前の操作を取り消せる。誰がいつ何をしたかを履歴に残す |
| カメラ | 相手の映像をホイール・ピンチで拡大し、ドラッグで動かす。ダブルクリックで元に戻る。「📷 高画質で撮る」で相手のカメラからフル解像度の静止画を取り寄せ、カードの文字を読める |
| スマホをカメラに | 「スマホをカメラにする」の QR コードを読み取ると、スマホをカメラ専用の端末にできる。リンクには自分専用の合言葉が入っているので、他の人には送らない。漏れたときは「合言葉を作り直す」で古いリンクを無効にできる |
| 自分のカメラの確認 | 相手の映像の右上に、自分が送っている映像を小さく表示する。クリックすると大きく表示し、拡大して文字が読めるか確かめられる |
| 観戦 | 招待リンクから「観戦する」を選ぶと、LP などの状態と両方のプレイヤーのカメラ映像を見られる(操作はできない)。観戦者は4人まで。ホストは観戦者を退出させられる |
| 部屋を閉じる | ホストが押すと、全員を切断し、その部屋の保存データを消す。最後に使ってから1日たった部屋のデータも自動で消える |

ルールの操作を止めることはしません(実物のカードにはルールを上書きする効果があるため)。公式ルールとの照らし合わせは [docs/rules.md](docs/rules.md) にあります。

## 使い方

1. 公開版を開いて名前を入れ、「ルームを作る」を押す
2. 「招待リンクをコピー」で、相手にリンクを送る
3. 相手がリンクを開くと、自動でつながる
4. それぞれ「自分のカメラ」でカメラを選ぶ(またはスマホをカメラにする)
5. コイントスやサイコロで先攻を決め、ターン欄の先攻ボタンで選ぶ
6. 決着したら勝者を確定し、「次のデュエル」へ進む
7. 遊び終わったら、ホストが「部屋を閉じる」を押す

招待リンクを知っている人は誰でも参加できます。信頼できる相手にだけ送ってください。リンクを開いた人は「対戦する」か「観戦する」を選びます。対戦の席が埋まっていれば観戦になります。閉じた部屋の招待リンクは使い回さず、次に遊ぶときは新しく部屋を作ってください(古いリンクのままだと、他の人がホストになれてしまいます)。

## 注意(β版)

- 回線によっては P2P でつながらないことがあります。その場合は TURN サーバーの設定が要ります(下の「設定」)。
- 通信相手には、お互いの IP アドレスが見えます(WebRTC の仕組み上)。
- 接続の仲介には PeerJS の公開サーバーを使っています。映像や操作の中身はそこを通りません。

セキュリティについては [docs/security.md](docs/security.md) にまとめています。

## 開発

```bash
npm install
npm run dev        # http://localhost:5173
npm run dev:lan    # スマホから LAN 経由で試す(HTTPS・自己署名証明書)
npm run build      # dist/ に静的ファイルを出力
```

開発モードでは、カメラの選択肢に「テスト映像」が出ます。カメラがなくても動作を試せます。

### 構成

| 場所 | 内容 |
|---|---|
| `src/game/state.ts` | デュエルの状態と更新ルール、受け取ったデータの検証 |
| `src/game/lpInput.ts` | LP 欄の入力(式)の解釈 |
| `src/net/room.ts` | ルームの接続、状態の同期、カメラ映像とスナップショットの送受信 |
| `src/media/camera.ts` | カメラの取得、送信画質の調整、静止画の撮影 |
| `src/components/` | 画面 |
| `docs/` | 設計(`design.md`)、公式ルールとの照合(`rules.md`)、セキュリティレビュー(`security.md`) |

状態はルームを作った側(ホスト)が持ち、操作はホストで検証してから全員に配ります。サーバーは置いていません。

## 設定(任意・`.env`)

| 変数 | 用途 |
|---|---|
| `VITE_PEER_HOST` / `VITE_PEER_PORT` / `VITE_PEER_PATH` | 自前の PeerServer を使う場合に指定する(省略すると PeerJS の公開サーバーを使う) |
| `VITE_TURN_URL` / `VITE_TURN_USER` / `VITE_TURN_PASS` | P2P でつながらない回線向けの TURN サーバー |

`.env` は `.gitignore` に入っているので、コミットされません。
